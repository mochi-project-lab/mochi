# Mochi — browser extension

A small pixel pet in the corner of every page. On memescopes it sniffs the Solana coin you hover and tells you if it
looks legit. On any site it warns you when the site looks like a wallet drainer.

One source tree runs on Chrome, Edge (Manifest V3, service worker) and Firefox 128+ (MV3, event page — the manifest is
rewritten at pack time). Vanilla JS, no build step, no remote code, no API keys.

## Install (unpacked, for development)

**Chrome / Edge**
1. Open `chrome://extensions` (or `edge://extensions`) and turn on **Developer mode**.
2. **Load unpacked** → pick this `extension/` folder.
3. Start the server (`node server/index.js` in `Mochi/`, port 4400) or set another backend URL in the pet's settings.

**Firefox**
1. `node scripts/pack-extension.mjs` (from `Mochi/`).
2. Open `about:debugging#/runtime/this-firefox` → **Load Temporary Add-on…** → pick `server/public-dl/mochi-extension-firefox.zip`.
3. If the pet doesn't appear, click the toolbar icon → **Allow on all sites** (Firefox lets you turn site access off).

## Files

| file | what it does |
|---|---|
| `manifest.json` | MV3 manifest (Chrome/Edge form; Firefox form is generated by `scripts/pack-extension.mjs`) |
| `background.js` | the only part that talks to the backend; caches scans (3 min) and site checks (6 h); per-tab chat history |
| `content.js` | the pet, bubble, chat panel, scan cards, hover sniffing on memescopes, site signals; all inside a closed shadow root |
| `common.js` | defaults, personas, memescope host list |
| `sprite.js` | pet sprite, identical copy of `shared/sprite.js` |
| `popup.*`, `options.*`, `ui.css` | toolbar popup and settings page |
| `icons/` | built by `scripts/build-icons.mjs` from the sprite |

Rebuild icons: `node scripts/build-icons.mjs`. Build store zips: `node scripts/pack-extension.mjs` →
`server/public-dl/mochi-extension.zip` (Chrome/Edge) and `mochi-extension-firefox.zip`.

## Commands

Click the pet or press **Alt+P** to open the chat. `/scan [address]`, `/site`, `/hide`, `/sleep`, `/help`,
`/name <name>`, `/color <color>`, `/mood`, `/settings`, `/clear`. Anything else is a question about the current page.

## Permissions and why

| permission | why |
|---|---|
| `storage` | saves your settings (name, colour, persona, toggles, pet position, hidden sites, optional OpenRouter key) and short-lived caches |
| content scripts on `http://*/*`, `https://*/*` | the pet has to be drawn on the pages you visit, and site warnings have to run on any site — phishing pages are on unknown domains, so there is no shorter list. Hover sniffing itself only turns on for memescope hosts |
| `commands` (Alt+P) | keyboard shortcut to open the chat |
| Firefox only: `host_permissions` `http://*/*`, `https://*/*` | same access as the content scripts; Firefox shows it as a separate switch, the popup can ask for it |

No `tabs`, `scripting`, `webRequest`, `cookies` or `history` permissions. No remote code: every script ships in the package.

## Privacy

The extension talks only to the backend URL in settings (default `https://petmochi.app`). It sends:

- **Coin scan** (when you click "sniff?", use `/scan`, or turn on auto-scan): the Solana address, your persona and pet name.
- **Site check** (once per domain per 6 h, if "Site warnings" is on; skipped for localhost and private IPs): the site's
  origin (`https://example.com/` — never the path or query), two yes/no signals (has a "connect wallet" button, has a
  seed-phrase field) and, only when one of those is yes, the page title.
- **Chat** (only when you send a message): your last ~10 chat lines, the page URL and title, up to 4000 characters of the
  page's visible text, and the last coin you scanned.
- **Your OpenRouter key** (only if you set one): as the `X-OpenRouter-Key` header with each request, so the server uses
  your key for AI answers. The server does not log or store it. The key itself is kept in `chrome.storage.local` in this browser.

Nothing else: no browsing history, no cookies, no wallet addresses, no analytics. Chat history and caches live in
`storage.session` and are gone when the browser closes. Seed-phrase fields are only detected by their labels; what you
type in them is never read.
